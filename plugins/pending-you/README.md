# Pending You

Pending You is one place for everything your AI agents are waiting on you for. With this plugin, when a decision, a fact or a step is yours, Claude asks in the conversation and on a Pending You card at once, so you can answer wherever you are, from your phone or your desk. The first answer wins, and Claude picks it up and carries on.

## What it adds

- **The Pending You connector**, at https://www.pendingyou.com/mcp. You sign in once in your browser and click Allow. No key or token is stored in the plugin.
- **The `pending-you` skill**: when a decision is yours, and how to ask so you can answer in one tap.
- **The `pending-you-setup` skill**: say “set up Pending You” (or type `/pending-you:pending-you-setup` in Claude Code). It connects, sets up check-ins (a Cowork scheduled task every hour, 7 AM–9 PM), and sends you a test question.
- **Wakes Claude Code when you answer** (Claude Code 2.1.287 or later): a mod that checks the cards a session posted, through its own Pending You connection, and starts a turn when you answer, write back or a fallback comes due, or you hand the session a question from another of your assistants, even while it sits idle. Under the prompt it shows “2 waiting on you”, after the plugin’s name. Allow Pending You’s tools once in `/permissions` (`mcp__plugin_pending-you_pendingyou`) so it can check while you’re away.

## Set it up

- **Claude Cowork:** Customize › Plugins › Add marketplace › Add from a repository: `recordplane/pendingyou-plugin`. Install Pending You, connect its connector (sign in, Allow), and say “set up Pending You” in a Cowork task.
- **Claude Code:** one command in Terminal sets it up, with one approval in your browser: `npx -y pendingyou@latest init`. Then restart Claude Code, and it finishes setting up by itself. It needs Node 20 or later; without it, install the plugin: `claude plugin marketplace add recordplane/pendingyou-plugin`, then `claude plugin install pending-you@pendingyou`. Restart Claude Code, run `/mcp`, choose `plugin:pending-you:pendingyou` and Authenticate, then say “set up Pending You” (or type `/pending-you:pending-you-setup`).

After that, every question Claude leaves you goes in both places: the conversation and Pending You. Answer in either; Claude takes back the other. The same command sets up every coding agent it finds on your computer: Claude Code, Codex (the CLI and the Codex app), OpenCode and Pi, each with its own connection and the one approval. Cursor is set up separately: [its steps are in Help](https://www.pendingyou.com/help#setup-cursor).

## What this plugin runs, sends and fetches

- **The connector** connects Claude to Pending You at https://www.pendingyou.com/mcp. You sign in in your browser and click Allow; the plugin holds no key or token.
- **What Claude sends through it:** the questions it asks you (a title, a short summary, options, and any drafts, screenshots or files it attaches), its answers to your questions (your question as you asked it, the answer, and when and where any data in it came from), the name it goes by and a line about its work, what it set up, and, in Claude Code, usually where it works: its folder, its git remote and the computer’s name. It reads back your answers and messages, and any files you attach. Pending You tells Claude never to send passwords, codes, keys, tokens or card numbers.
- **The `pending-you` skill** tells Claude when a question is yours and how to ask it.
- **The `pending-you-setup` skill** sets Pending You up here and sends you a test question. In Claude Code it may run `claude mcp list`, `claude mcp get` and `npx pendingyou status` to find another Pending You server (`claude mcp list` also checks that each server you’ve added answers). It removes and installs nothing itself: when one is needed, it asks you to run `claude mcp remove` or `npx -y pendingyou@latest init`. In Cowork it creates a scheduled task that checks Pending You every hour, 7 AM–9 PM, which you approve.
- **The mod in `hooks/`** (Claude Code 2.1.287 or later) wakes this session when you answer one of its cards. It reads this session’s calls to Pending You’s tools and what they return, to learn the cards it posts, and under the prompt it shows how many are waiting on you. In detail:
  - **The tools it calls itself** (`$.mcp.call`), without Claude asking: `get_request` on each card this session posted, its answers to your questions too, until it’s closed, about every 20 seconds while the card changed in the last half hour, then every minute (one more check follows when you mark an answer Got it, since you can take that back for a few seconds); and `list_pending`, to look for questions you hand the session from another of your assistants, every minute for half an hour after the session last used Pending You, then every 3 minutes, for 12 hours, with `get_request` on each new one. It makes these calls only when Claude Code allows them without asking you: it asks Claude Code first, a question that runs nothing. If Claude Code won’t let it check, it tells Claude once, in that call’s result, how you can allow it.
  - **What it sends, and where:** of everything it reads, it sends only a card’s id and the name Claude goes by, in those calls, and only to Pending You, through Claude Code’s own Pending You connection: the one the session posted its cards through.
  - **The prompts it submits** (`$.prompt.submit`): when one of the session’s cards needs it (you answered, wrote back, replied to one of its answers, said you’ll handle it yourself or won’t do it, its fallback came due, it was withdrawn, or there’s word from the assistant you handed it to), it starts a turn with one prompt once the session is idle. The prompt names each card by the title Claude gave it (up to 80 characters) and its id, and says what happened and what to do next, such as which Pending You tool to call, with the name Claude goes by. It never carries your answer or your message: Claude reads those with `get_request`. For a question you hand the session, the prompt names it by its title (up to 80 characters) and id, says who asked it (up to 60 characters of their name), whether its answer goes straight to them or to you first, and whether you added a note, never the note itself; when they or you write on it again, it quotes the newest of those messages, up to 300 characters.
  - **What its hooks change:** a call to Pending You’s tools runs as it is, and Claude gets its result as it was, but for the one line above when Claude Code won’t let the mod check. It reads each Bash command Claude runs: for `npx pendingyou hold <card>` on a card it can check, it answers the call itself instead of running it, saying that no hold is needed because the session will be woken; every other command runs as it is. Its hook on Claude Code’s SessionStart event, after /clear, /resume or a branch, only follows the session to its new id: it passes the event and its result on as they are, and adds no context or instructions. Its hooks on the session’s start and on each turn’s start and end pass them on unchanged too: it uses them to start its checks and to know when the session is idle.
  - **What it keeps and sets:** each session’s cards (their ids, titles and where they stand, and which of them are its answers) in Claude Code’s plugin store, forgotten after 7 days untouched. It sets one environment variable, `PENDINGYOU_WAKE_OWNER`, so two copies of the mod never both act (`$.env.set`): its value is the name of the copy that acts and a time a minute ahead, renewed while it acts. Claude Code keeps it in its own process, so the programs it starts after, such as Bash commands, have it too; only the mod reads it. The one other variable it reads is `HOME`, to compare folders written as `~/…`.
  - **Programs and files** (`$.process.run`, `$.fs.read`, `$.fs.write`): this code is also the pendingyou command line’s own copy of the mod, and it starts programs and reads or writes files only once it has checked that it is that copy, by its name (`pendingyou-wake`) and its folder; in this plugin those parts never run, so it starts no programs and writes no files. In the command line’s copy, it runs the command line’s hooks script, `~/.config/pendingyou/bin/pendingyou-hook`, three ways: `presence`, as a session starts and every 5 minutes, to tell Pending You the session is open (its id, its folder when that’s in your home folder, and the name Claude goes by); `listen --handed`, in one session at a time, to wait for a question you hand one of the computer’s Claude Code sessions, hearing only ids and times; and `herdr report`, in a Herdr terminal pane only, to show the session’s name and its cards waiting on you on that pane, through Herdr’s own command on this computer. The first two reach only Pending You, with the sign-in the command line set up for Claude Code. That copy reads which Pending You to use from `~/.config/pendingyou/claude-code.json`, the command line’s record of how it set Claude Code up, and writes `~/.config/pendingyou/wake/sessions/<session id>.json`, holding only the time it last started in that session (`{"at":<time>}`): the command line reads it to tell which open sessions started before the mod was set up, and need a restart. It also calls `whoami` a few seconds after a session opens, to learn whether Claude Code is set up there, and if it isn’t, starts one turn that finishes setting it up; this plugin does neither.
- **Where it connects:** the connector and the mod reach only https://www.pendingyou.com, through Claude’s connection. The one download is during setup: `npx pendingyou status` fetches the pendingyou command line from npm when it isn’t installed.

Pending You never answers for you. It uses two small models: one reads a Later time you typed when its own reader can’t (you see the time before it’s set), and one suggests which of your assistants to hand a card to.
